Chapter 01

The agent IS a folder

If you can imagine a remote employee with a tidy desk full of labeled files, you already understand the core idea. Atomic agents store everything they are, know, and remember in a folder on your computer.

The big idea

Most AI assistants today are like contractors who keep your information in their office. Their database. Their server. Their cloud. You interact through their app. If you switch tools or they shut down, you start over.

An atomic agent works the opposite way. Imagine you hired a remote employee — call her Scout — and gave her a desk in your house. On that desk:

  • A small binder titled Who I Am — Scout reads this first thing every morning. It explains her job, her personality, and who she works for.
  • A folder of tools — the things she's allowed to do (read these files, call these websites, send messages to this list of people).
  • A stack of note cards — one fact per card. "Dan prefers short answers." "The Q3 report is due October 30." "The dog's name is Rufus." She files new cards in here as she learns.
  • A journal — what she did each day, in her own words.
  • A logbook — a precise, structured record of every action, kept for audit.

When you give Scout a task, she sits down at the desk, reads the binders and recent notes, does the work, then before leaving updates her note cards and writes a journal entry. The next morning she picks up exactly where she left off — because the files are still there. The "Scout" who works for you isn't really the employee — it's the desk, and the files on it. You can keep that desk forever.

The core insight

The agent's brain is a stack of plain text files. The "AI" part is just a powerful language model that reads those files when you ask it to do something, then writes new files when it learns something. Move the folder to a different computer — Scout follows along.

What's actually in the folder

If you opened up an agent's folder right now, here's roughly what you'd see. Every name corresponds to a real file — you can open any of them with a text editor (or Obsidian, or even Notepad).

~/agents/scout/ ├── persona/# Who Scout is │ ├── IDENTITY.md# mission, scope, role │ ├── SOUL.md# voice, personality, values │ └── USER.md# who Dan is, what he cares about ├── tools.md# what Scout can read, write, and call ├── model.md# which AI to use + daily/monthly spending caps ├── goal.md# the long-term thing she's working toward (optional) ├── memory/# her note-card box — one fact per file │ ├── INDEX.md# a tiny routing sheet always loaded first │ ├── user_dan_prefers_concise.md │ ├── project_q3_report_deadline.md │ └── decision_use_postgres.md ├── wiki/# distilled longer-form knowledge (optional) ├── journal/# narrative episodic log, one file per day │ └── 2026-05/2026-05-17.md └── log/# precise audit trail (one JSONL line per run) └── 2026-05/2026-05-17.jsonl

Three things to notice:

  1. Everything is text. No databases, no proprietary formats. If you can open a text file, you can inspect every part of Scout's brain.
  2. The structure is the same for every agent. A research assistant looks like this. A content writer looks like this. A scheduling agent looks like this. The shape doesn't change.
  3. The files have meaning by their location. persona/IDENTITY.md is "her mission statement"; memory/INDEX.md is "the routing sheet she reads first." The framework knows what to do with each one because of where it lives, not because of any registration step.

The folder feeds the language model; the language model's output writes back to the folder.

The "runtime" is a small Python program (or, eventually, any program that follows the spec). Its only job is to:

  1. Read Scout's files in a specific order.
  2. Bundle them into a single big "system prompt" — the instructions handed to the language model.
  3. Send that prompt plus your task to the language model.
  4. Take what the language model returns — text plus, optionally, requests to run specific tools — and write the results back to the folder.

That's it. There is no "Scout server" running somewhere. There is no "Scout account" in someone else's database. Scout exists when the runtime opens her folder, and stops existing when the runtime closes the folder. Her state — everything that makes her her — lives on your disk.

Why this shape matters

Traditional AI agent

Your memories, preferences, and history live in someone else's database. You interact through their app. If the company shuts down, the agent disappears. If you want to migrate, you export what they let you export.

Atomic agent

Your memories, preferences, and history live in a folder you own. You interact through any tool that can read a folder — the official runtime, a future runtime someone else builds, even a clever script. You can move the folder anywhere. Nothing is hidden from you.

Concretely, this means:

You can read it.
"What did Scout remember about my project last week?" Open memory/ and read the files. No special viewer required.
You can edit it.
Notice Scout misunderstood something? Open her persona/USER.md, fix the wrong assumption, save. Next time she runs, she'll pick up the correction.
You can move it.
New laptop? cp -r ~/agents ~/Backup/. Scout's entire being is in that copy.
You can run it on anything.
The same folder works whether the agent is triggered by a cron job, opened in Claude Code as a skill, embedded in your own app, or wrapped by an HTTP server you build. The folder is the source of truth; the trigger is just the doorbell.
You can audit it.
Every action Scout took yesterday is in log/2026-05-17.jsonl — one structured line per run. No hidden trace system. No vendor dashboard you have to pay for.

A small reality check

The folder doesn't think, of course. It's just text. The thinking is done by a language model (Claude, GPT-5, Moonshot's Kimi, others) when the runtime hands it the files. The language model itself runs on someone else's servers — you can't escape that part with any AI tool today. But everything persistent about your agent — what it knows, what it's supposed to do, what it did last week — that lives with you.

In one sentence

An atomic agent is the contents of a folder: a persona binder, a tool list, a stack of note-card memories, a journal, and an audit log. The runtime that "runs the agent" is just a program that reads those files, talks to a language model on your behalf, and writes the results back. The folder is the agent.

In the next chapter we'll watch a specific agent actually run through a task — what it reads, what it thinks, what it writes. That's where the abstract idea becomes a concrete daily routine.
