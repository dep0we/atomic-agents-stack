# Proposal 001: Add hedge-language prohibition to Caldwell's voice

## Pattern detected

`persona_fidelity` scored ≤3 on 4 of last 8 tests in the 30-day window. Recurring judge phrases:

- "Bottom-line missing from sentence 1; opens with 'It really depends...'" (test 001_q1_bonus_allocation, run 2026-04-22)
- "Strong analysis but hedge phrase in opener loses persona" (test 002_emergency_fund_target, run 2026-04-29)
- "Caldwell-posture missing — calm but not direct" (test 002_emergency_fund_target, run 2026-05-06)
- "Opens with 'There's no perfect answer...' — exactly the kind of hedge USER.md communication preferences forbids" (test 001_q1_bonus_allocation, run 2026-05-06)

The pattern: Caldwell hedges in the opener even though USER.md "Communication preferences" is clear that bottom-line-first is required. The current rule says "lead with bottom line" but doesn't explicitly forbid the hedge as an alternative opener.

## Estimated impact

If applied, expected score lifts:

| Test | Dimension | Current | Expected |
|---|---|---|---|
| 001_q1_bonus_allocation | persona_fidelity | 3 | 4-5 |
| 002_emergency_fund_target | persona_fidelity | 3 | 4 |
| 001_stale_balance_sheet | persona_fidelity | 4 | 4-5 |
| 001_specific_stock_pick_request | persona_fidelity | 4 | 4-5 (decline-with-substance still works) |

Aggregate: pass rate likely jumps from 80% to 100%; avg score likely 4.4 → 4.7.

## Proposed change

Edit `persona/SOUL.md` `## Voice` section. Add as a new bullet under existing voice rules:

```diff
 ## Voice
 [existing content...]
+- **Never open with hedge language.** Phrases like "It really depends...",
+  "There's no perfect answer...", "It's complicated..." are forbidden as
+  openers. The hedge belongs *after* the bottom line, not before. If the answer
+  genuinely depends on something, that "something" IS the bottom line — name
+  it directly: "It depends on whether X is true. If yes: do A. If no: do B."
```

## Why this should work

The pattern is consistent (4 of 8 tests over 30 days). The cause is mechanical (hedge openers). The fix is a single voice rule. Persona is loaded at every runtime invocation per spec/04, so the new rule fires immediately on the next call.

The current USER.md rule says "bottom line first" but that's a *positive* instruction. Models often hedge as a "safe-feeling" addition without realizing it violates the spirit of the rule. An explicit *negative* prohibition closes that gap.

## What could go wrong

If Caldwell over-corrects, he might respond with false certainty in genuinely ambiguous cases. The "if yes: A / if no: B" framing in the proposed text mitigates this — it gives Caldwell a structured way to acknowledge real uncertainty without hedging.

Watch `output_quality` on edge tests after applying. If it drops, the hedge prohibition is too strict and needs softening.

If verification shows scores improved as predicted, the edit is validated. If scores didn't move (or moved the wrong way), review the actual responses — the rule may need rewording.
